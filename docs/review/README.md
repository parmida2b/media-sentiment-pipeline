# بررسی یکپارچگی و باگ‌یابی کد — برنامه‌ی کار

این پوشه گزارش‌های بررسی کد و ریپوزیتوری را نگه می‌دارد. اگر سشن قطع شد، کار از
[`PROGRESS.md`](PROGRESS.md) ادامه پیدا می‌کند.

## قواعد
1. تا پایان مرحله‌ی ۵ هیچ کدی تغییر نمی‌کند؛ فقط بررسی و گزارش.
2. هر مشکل با شواهد ثبت می‌شود (فایل:خط یا خروجی اجرا)؛ حدس به‌عنوان باگ ثبت نمی‌شود.
3. هر باگ قبل از اصلاح با یک تست بازتولید می‌شود؛ اصلاح‌ها در commitهای کوچک و جدا.
4. بعد از هر مرحله: به‌روزرسانی `PROGRESS.md` و commit + push روی `claude/code-review-integrity-kc1fy1`.

## مراحل، مدل و effort پیشنهادی

| # | مرحله | مدل / effort | خروجی |
|---|---|---|---|
| ۰ | نقشه‌ی پروژه و جریان داده | Sonnet 5.5 / medium | `01-architecture.md` |
| ۱ | نصب در محیط تمیز، اجرای تست‌ها، اجرای کامل pipeline (baseline) | Sonnet 5.5 / medium | `02-baseline.md` |
| ۲ | ابزارهای خودکار: ruff، mypy، vulture، pip-audit، gitleaks | Sonnet 5.5 / medium | `03-static-analysis.md` |
| ۳ | بررسی مرز ماژول‌ها (schema، ستون‌ها، مسیرها، کانفیگ) | Opus 5.5 / high | `04-integration.md` |
| ۴ | بررسی عمیق به ترتیب ریسک (متن فارسی، حالت‌های مرزی، آمار/ML) | Opus 5.5 / high | `05-deep-review.md` |
| ۵ | لیست نهایی مشکلات با اولویت‌بندی | Opus 5.5 / high | `FINDINGS.md` |
| ۶ | رفع: تست بازتولید ← اصلاح ← commit کوچک (بعد از تأیید کاربر) | Opus 5.5 / medium–high | commitها + به‌روزرسانی `FINDINGS.md` |

نکته: `xhigh`/`max` فقط برای یک باگ مشخص و سخت. مدل با `/model` عوض می‌شود.

## سطح اهمیت
- **بحرانی**: خروجی/نتیجه‌ی تحقیق را غلط می‌کند یا pipeline را می‌شکند.
- **مهم**: در شرایط مشخصی خطا می‌دهد یا داده را بی‌صدا از دست می‌دهد.
- **جزئی**: کیفیت کد، کد مرده، ناسازگاری مستندات.
