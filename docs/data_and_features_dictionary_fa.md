# راهنمای داده و فیچرها — برای تحلیل/داشبورد

این سند برای کسیه که قراره روی داده‌ی جمع‌آوری‌شده از یوتیوب **تحلیل و
داشبورد** بسازه، نه برای کسی که کد پایپ‌لاین رو می‌نویسه. هدف اینه که بدون
خوندن کد، بفهمید هر ستون یعنی چی، چقدر می‌شه بهش اعتماد کرد، و چه محدودیتی
داره.

---

## ۱. کدوم فایل رو باز کنم؟

داده زیر `data/raw/{topic_id}/` (مثلاً `data/raw/iran_us_war/`) ذخیره می‌شه.
برای کار تحلیلی/Power BI **این فایل رو بگیرید**:

```
youtube_raw_export.csv
```

(نه `youtube_comments_v2.jsonl` — همون داده‌س ولی فرمت JSON خط‌به‌خط داره که
برای Excel/Power BI راحت نیست؛ اون برای کد پایتونیه.)

هر ردیف این CSV = **یک کامنت یوتیوب**.

### فایل‌های کمکی دیگه (اختیاری، فقط اگه لازم شد)
| فایل | چیه |
|---|---|
| `video_geo_metadata.jsonl` | یک ردیف به‌ازای هر **ویدیو** (نه کامنت): آیا مرتبط بود، لحن/دیدگاه منبع چی بود |
| `youtube_skipped_videos.csv` | لیست ویدیوهایی که رد شدن (بی‌ربط تشخیص داده شدن) — برای گزارش پوشش، نه تحلیل احساسات |
| `youtube_runs.csv` | لاگ هر بار اجرای جمع‌آوری (چند رکورد اومد، چقدر quota مصرف شد) — صرفاً عملیاتیه |

---

## ⚠️ ۲. مهم‌ترین نکته قبل از هر چیز: **لیبل احساسات هنوز روی این داده نیست**

این CSV فقط **داده‌ی خام** کامنت‌هاست. ستون‌هایی مثل `sentiment` /
`stance` / `emotion` که نتیجه‌ی تحلیل باشن، **هنوز در این فایل وجود ندارن** —
اون مرحله (لیبل‌زدن با LLM روی کل داده) هنوز انجام نشده و بعداً به‌صورت یک
فایل جدا (`data/processed/...`) اضافه می‌شه.

**چیزی که همین الان می‌شه باهاش کار کرد:**
- حجم کامنت در طول زمان (`created_at_utc`)
- توزیع بین منابع/کانال‌ها و دیدگاه‌ها (`source_container`, و بعداً join با `video_geo_metadata.jsonl`)
- توزیع زبان (`language_detected`)
- سرنخ اولیه از ریسک ربات (`automation_risk_score`)
- میزان تعامل (`engagement_*`)

یعنی می‌تونید اسکلت داشبورد (نمودار روند زمانی، breakdown بر اساس منبع/زبان،
فیلتر ریسک ربات) رو از همین الان بسازید؛ فقط ستون «احساسات» بعداً اضافه
می‌شه و باید با `platform_content_id` به همین جدول join بشه.

## ۳. توضیح ستون‌ها

### هویت و زمان
| ستون | توضیح |
|---|---|
| `platform` | همیشه `youtube` (این سند فقط برای یوتیوبه؛ Reddit/X بعداً همین فرمت رو دارن) |
| `platform_content_id` | آیدی خودِ کامنت در یوتیوب — کلید یکتا برای هر ردیف |
| `content_type` | `comment` یا `reply` |
| `created_at_utc` | زمان **انتشار** کامنت (UTC) — این ستون رو برای نمودار روند زمانی استفاده کنید |
| `collected_at_utc` | زمانی که خودِ اسکریپت این کامنت رو دانلود کرده — با `created_at_utc` قاطی نشه |
| `text_raw` | متن کامنت |
| `author_hash` | به‌جای نام کاربری، یک کد رمزشده (برای حفظ حریم خصوصی) — برای شمارش «چند کامنت از یک نفر» قابل استفاده‌ست، ولی هویت واقعی رو نشون نمی‌ده |
| `project_week` | هفته‌ی پروژه (`W01`..`W21`) که این کامنت توش افتاده، یا `OUT` اگه بیرون بازه‌ی پروژه بود |
| `in_window` | `True`/`False` — آیا داخل بازه‌ی زمانی رسمی پروژه‌ست؟ برای تحلیل نهایی معمولاً باید `in_window=True` رو فیلتر کنید |
| `is_partial_week` | آیا این هفته یک هفته‌ی کامل بوده یا فقط بخشی از اون جمع‌آوری شده (مثلاً هفته‌ی اول/آخر پروژه) |
| `query_id` | کدوم عبارت جست‌وجو باعث پیدا شدن این ویدیو شده |
| `collection_run_id` | شناسه‌ی اجرای اسکریپتی که این رکورد رو آورده |

### منبع
| ستون | توضیح |
|---|---|
| `source_id` | آیدی کانال در رجیستری منابع پروژه (مثلاً `YT-003`)؛ اگه کانال تو رجیستری نبود خالیه |
| `source_container` | اسم قابل‌خوندن کانال (مثلاً «Press TV») |
| `source_container_id` | آیدی یوتیوبی کانال |
| `source_parent_id` / `source_parent_title` | آیدی/عنوان ویدیویی که کامنت زیرش بوده |
| `parent_id` | اگه این ردیف یک **ریپلای** باشه، آیدی کامنت والدش |
| `discovery_route` | چطور این ویدیو پیدا شده: `query_search` (از جست‌وجو) یا `source_scope` (از کانال‌های شناخته‌شده) |
| `matched_query_ids` | همه‌ی کوئری‌هایی که به این ویدیو رسیدن (چندتا می‌تونه باشه) |
| `sampling_method` | اگه یک ویدیو کامنت خیلی زیاد داشته، `random` (نمونه‌گیری تصادفی با seed ثابت انجام شده)؛ اگه `none`، همه‌ی کامنت‌ها نگه داشته شدن |
| `items_kept` / `source_total_available` | چندتا کامنت نگه داشته شده از چندتای موجود (برای فهمیدن این‌که این ویدیو نمونه‌برداری شده یا کامل گرفته شده) |

### تعامل (Engagement)
| ستون | توضیح |
|---|---|
| `engagement_score` | لایک کامنت |
| `engagement_replies` | تعداد ریپلای زیر این کامنت |
| سایر `engagement_*` | برای یوتیوب معمولاً خالی‌ان (این ستون‌ها برای Reddit/X هم استفاده می‌شن که فیلدهای متفاوتی دارن) |

### نویسنده
| ستون | توضیح |
|---|---|
| `author_is_verified`, `author_follower_count`, `author_account_age_days` | ⚠️ **یوتیوب این‌ها رو برای کامنت‌گذارها نمی‌ده** — همیشه خالی‌ان، طراحی‌شده برای پلتفرم‌های دیگه |
| `automation_risk_score` | عددی بین ۰ تا ۱: چقدر این کامنت رفتار مشکوک به ربات/اسپم داره (تکرار متن، ارسال پشت‌سرهم، چگالی لینک/هشتگ). **این یک حکم قطعی «رباته» نیست**، فقط هشدار برای فیلتر بعدیه — پیشنهاد: برای تحلیل احساسات، کامنت‌های خیلی بالای این امتیاز (مثلاً ≥۰.۷) رو جدا نگه دارید یا با احتیاط تفسیر کنید، نه اینکه بی‌چون‌وچرا حذفشون کنید |

> نکته: یه امتیاز ریسک **کاربر-محور** دقیق‌تر (`automation_risk_score_user`،
> که رفتار یک نفر رو در کل کانال‌ها می‌بینه، نه فقط یک ویدیو) در فایل جداگانه‌ی
> `data/interim/clean.jsonl` هست (خروجی `join_and_clean.py`) — اگه لازم شد
> بگید تا اون هم به همین شکل CSV آماده بشه.

### زبان و وضعیت
| ستون | توضیح |
|---|---|
| `language_reported` | معمولاً خالی (یوتیوب زبان کامنت رو گزارش نمی‌ده) |
| `language_detected` | زبان تشخیص داده‌شده توسط خودِ کد: `fa` / `en` / `ar` |
| `language_confidence` | اطمینان به تشخیص زبان (۰ تا ۱) |
| `content_status` | وضعیت محتوا (مثلاً حذف‌شده/موجود) |

### جغرافیا
| ستون | توضیح |
|---|---|
| `geo_method` | روش تخمین محل کامنت‌گذار: `text_place` (خودمعرفی صریح در متن)، `source_community` (بر اساس کانال میزبان)، یا `language_weak` (فقط زبان) |
| `country_or_region` | کد کشور (`IR`/`US`/...) یا `unknown` |
| `geo_confidence` | `high` / `medium` / `low` (رتبه‌ای، نه عدد) |
| `geo_granularity` | `country` یا `unknown` |
| `geo_limitations` | توضیح متنی محدودیت همون روش |

⚠️ **مهم‌ترین محدودیت این بخش:** یوتیوب هیچ اطلاعات مکانی واقعی از
کامنت‌گذار نمی‌ده. پس اکثر ردیف‌ها `country_or_region = unknown` خواهند
بود — این باگ نیست، محدودیت واقعی دیتاست. هر جا `geo_method = source_community`
بود، یعنی کشور واقعاً مال **کانال ویدیو**ست نه لزوماً محل زندگی کامنت‌گذار؛
در نمودار جغرافیایی حتماً این تفاوت رو مشخص کنید (مثلاً با رنگ/برچسب جدا).

## ۴. چند نکته‌ی عملی برای شروع تحلیل

1. **فیلتر اول همیشه:** `in_window = True` (بیرون بازه‌ی پروژه رو کنار بذارید مگر تحلیل جداگانه بخواید).
2. **دیدوپ رایگانه:** هر ردیف با `platform_content_id` یکتاست، پس نگران کامنت تکراری نباشید.
3. **برای join با دیدگاه/لحن رسانه:** `source_parent_id` (آیدی ویدیو) رو با `video_id` در `video_geo_metadata.jsonl` جوین کنید تا `perspective` (state_media/western/independent/diaspora/other) به هر کامنت برسه.
4. **داده‌ی قدیمی جدا نگه‌دار:** اگه فایل‌های خیلی قدیمی‌تر (`youtube_comments_1404-*.jsonl`, پیش از ۷ آگوست) هم دیدید، اون‌ها فرمت قدیمی‌تری دارن (بدون خیلی از این ستون‌ها، و نام کاربری خام به‌جای هش) — فعلاً برای تحلیل جدید سراغشون نرید مگر گفته بشه.

## ۵. اگه چیزی گنگ بود

اگه یه ستون خالی بود یا مقداری دیدید که این‌جا توضیح داده نشده، قبل از حذفش
یا نادیده گرفتنش بپرسید — خیلی از خالی‌بودن‌ها (مثل `author_follower_count`)
عمدی و مستندن (یوتیوب اون داده رو نمی‌ده)، نه خطا.
