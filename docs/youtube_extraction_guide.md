# راهنمای ساده‌ی استخراج داده از یوتیوب (نسخه v2 / incremental)

این فایل توضیح می‌دهد که آخرین نسخه‌ی کد جمع‌آوری کامنت‌های یوتیوب چه کار می‌کند —
مناسب برای کسی که تازه با پروژه آشنا می‌شود.

فایل اصلی: [`src/ingestion/youtube_extract_incremental.py`](../src/ingestion/youtube_extract_incremental.py)

> نکته: این نسخه‌ی دوم (v2) کنار نسخه‌ی اول (`youtube_extract.py`) اجرا می‌شود و
> جایگزینش نمی‌شود. خروجی هرکدام در فایل جدا ذخیره می‌شود تا داده‌های قبلی دست‌نخورده بمانند.

---

## ۱. این اسکریپت اصلاً چیست؟

یک ربات پایتونی است که:
1. در یوتیوب دنبال ویدیوهایی می‌گردد که به موضوع پروژه (مثلاً تنش ایران-آمریکا) مربوط‌اند.
2. زیر آن ویدیوها، کامنت‌ها (و ریپلای‌هایشان) را می‌گیرد.
3. برای هر کامنت یک‌سری اطلاعات اضافه (فیچر) محاسبه می‌کند.
4. همه را در یک فایل JSON خط‌به‌خط (`.jsonl`) ذخیره می‌کند تا تیم تحلیل/برچسب‌گذاری ازش استفاده کند.

نکته‌ی مهم این نسخه: **افزایشی (incremental)** است، یعنی هر بار که اجرا می‌شود
از صفر شروع نمی‌کند؛ فقط دنبال چیزهای **جدید** می‌گردد (ویدیوهای تازه منتشرشده و
کامنت‌های تازه‌ی زیر ویدیوهای قبلاً دیده‌شده). این کار با «نشانه‌گذاری زمانی»
(watermark) در فایل `checkpoint.json` انجام می‌شود.

---

## ۲. چه فیچرهایی برای هر کامنت استخراج می‌شود؟

هر رکورد خروجی (تعریف‌شده در [`config/schema.py`](../config/schema.py)) شامل این فیلدهاست:

### اطلاعات پایه‌ی کامنت
| فیلد | توضیح |
|---|---|
| `text` | متن کامنت |
| `date` | زمان انتشار کامنت (به وقت UTC) |
| `source` / `platform` | همیشه `"youtube"` |
| `language` | زبان تشخیص داده‌شده‌ی متن (`fa` / `en` / `ar`) |
| `post_id` | آیدی ویدیویی که کامنت زیرش است |
| `post_title` | عنوان همان ویدیو |
| `is_reply` | آیا این یک ریپلای به کامنت دیگری است؟ |
| `reply_count` | چند ریپلای زیر این کامنت هست |
| `content_id` | آیدی خود کامنت در یوتیوب (برای جلوگیری از تکراری‌شدن داده) |
| `parent_id` | اگر ریپلای است، آیدی کامنت والد |

### اطلاعات نویسنده (بدون ذخیره‌ی نام واقعی!)
| فیلد | توضیح |
|---|---|
| `author_metadata.author_hash` | به‌جای اسم نمایشی کاربر، یک هش (کد رمزشده و غیرقابل‌بازگشت) از آیدی کانال کاربر ذخیره می‌شود — این برای حفظ حریم خصوصی است ([`author_hash.py`](../src/ingestion/author_hash.py)) |
| `author_metadata.author_channel_id` | آیدی کانال کاربر در یوتیوب |
| `author_metadata.like_count` | تعداد لایک کامنت |

### اطلاعات مربوط به جمع‌آوری داده (متادیتا)
| فیلد | توضیح |
|---|---|
| `collected_at_utc` | چه زمانی خودِ اسکریپت این کامنت را دانلود کرده (نه زمان انتشار کامنت) |
| `collection_run_id` | شناسه‌ی همان اجرای اسکریپت که این کامنت را آورده |
| `query_id` | کدام عبارتِ جست‌وجو یا کانال باعث پیدا شدن این ویدیو شده |

### اطلاعات جغرافیایی کامنت‌گذار
برخلاف نسخه‌ی قبلی، این تگ‌ها دیگر برای «کل ویدیو» یک‌بار محاسبه نمی‌شوند؛ برای **هر کامنت جداگانه**
با [`author_geo.py`](../src/ingestion/author_geo.py) ساخته می‌شوند، طبق واژگان کنترل‌شده‌ی سند پروژه
(بخش «دامنه‌ی جغرافیایی»):
| فیلد | توضیح |
|---|---|
| `geo_method` | یکی از `text_place` / `source_community` / `language_weak` (به همین ترتیب اولویت — `geotag`/`profile`/`timezone` هرگز در دسترس نیست چون API یوتیوب این‌ها را برای کامنت‌گذار نمی‌دهد) |
| `country_or_region` | کد کشور (مثل `IR`/`US`) یا `unknown` |
| `geo_confidence` | رتبه‌ای: `high` / `medium` / `low` (نه عدد) |
| `geo_granularity` | `country` یا `unknown` |
| `geo_limitations` | توضیح صریح محدودیت همان روش |

سه روش به این ترتیب امتحان می‌شوند:
1. **`text_place`** — فقط اگر متن خودِ کامنت یک عبارت **خودمعرفی** صریح داشته باشد
   (مثل «As an Iranian…» یا «من ایرانی‌ام»)، نه صرفاً اشاره به اسم «ایران»/«آمریکا».
   چون موضوع پروژه خودش ایران-آمریکاست، اگر هر اشاره‌ی ساده به این اسم‌ها را می‌پذیرفتیم،
   تقریباً همه‌ی کامنت‌ها (چون درباره‌ی همین موضوع حرف می‌زنند) غلط برچسب می‌خوردند.
2. **`source_community`** — اگر ویدیو از یکی از کانال‌های کیوریت‌شده‌ی رجیستری (مثل Press TV یا VOA Persian)
   آمده باشد، کشور همان کانال با `geo_confidence = "low"` ثبت می‌شود — چون این فقط درباره‌ی
   مخاطب/منشأ کانال است، نه لزوماً محل زندگی خودِ کامنت‌گذار.
3. **`language_weak`** — اگر هیچ‌کدام از بالا صدق نکرد، فقط زبان تشخیص‌داده‌شده‌ی متن ثبت می‌شود
   ولی `country_or_region` همیشه `unknown` می‌ماند — طبق قاعده‌ی صریح سند: «زبان متن هرگز به معنی
   کشور نویسنده نیست».

> جدا از این، هنوز یک تگ **دیدگاه/ربط‌بودن در سطح ویدیو** هم هست (بخش زیر)
> که چیز دیگری است: فقط برای فیلترکردن ویدیوهای نامرتبط و دسته‌بندی لحن رسانه به‌کار می‌رود،
> و دیگر مستقیماً در فیلدهای `geo_*` رکورد کامنت نمی‌نشیند.

### تگ‌گذاری دیدگاه ویدیو (فیلتر ربط + لحن رسانه)
این یکی همچنان **یک‌بار برای کل ویدیو** محاسبه می‌شود (با کمک LLM، در
[`geo_tagger.py`](../src/ingestion/geo_tagger.py)) و چیز جداگانه‌ای از جغرافیای کامنت‌گذار بالاست:
- `is_relevant`: آیا این ویدیو اصلاً به موضوع پروژه مربوط است؟ اگر نه، ویدیو کلاً رد می‌شود (skip)
  و کامنت‌هایش جمع‌آوری نمی‌شوند.
- `perspective`: لحن/جهت‌گیری منبع (`state_media` / `western` / `independent` / `diaspora` / `other`).
- نتیجه در `video_geo_metadata.jsonl` کش می‌شود تا برای یک ویدیو دوباره LLM صدا زده نشود.

این تگ در فیلدهای `geo_*` خودِ رکورد کامنت ذخیره **نمی‌شود** — چون درباره‌ی منشأ/لحن ویدیو است،
نه محل کامنت‌گذار، و قاطی‌کردن این دو دقیقاً همان مشکلی بود که نسخه‌ی قبلی این راهنما داشت.

### امتیاز ریسک ربات‌بودن
| فیلد | توضیح |
|---|---|
| `automation_risk_score` | عددی بین ۰ تا ۱ که نشان می‌دهد این کامنت چقدر «رفتار مشکوک به ربات/اسپم» دارد. **این یک حکم قطعی «ربات است» نیست**، فقط یک هشدار برای فیلتر بعدی است. |

سه سیگنال برای این امتیاز بررسی می‌شود ([`automation_risk.py`](../src/ingestion/automation_risk.py)):
- **تکرار متن مشابه:** آیا همین کامنت (تقریباً عیناً) چندبار در همان ویدیو تکرار شده؟
- **ارسال پشت‌سرهم:** آیا همان نویسنده چند کامنت را در فاصله‌ی کوتاهی (کمتر از ۶۰ ثانیه) فرستاده؟
- **چگالی لینک/هشتگ:** آیا متن پر از لینک یا هشتگ است؟

> محدودیت مهم: یوتیوب اطلاعاتی مثل «سن اکانت» یا «تعداد فالوور» نمی‌دهد،
> پس این امتیاز فقط از روی همین سه سیگنال ساده حساب می‌شود؛ دقیق‌تر از این نیست.

## ۳. فلوی کار (Workflow) — گام‌به‌گام

```
شروع
  │
  ▼
۱) خواندن آخرین وضعیت ذخیره‌شده (checkpoint.json)
   - از کجا جست‌وجوی قبلی متوقف شده بود؟ (watermark)
  │
  ▼
۲) مرحله‌ی «کشف» (Discovery) — پیدا کردن ویدیوهای جدید
   - برای هر عبارت جست‌وجو (از config/query_registry.yaml)
     × هر منطقه/زبان، در یوتیوب سرچ می‌کند
   - همچنین کانال‌های از‌پیش‌شناخته‌شده (channels.py) را چک می‌کند
   - فقط ویدیوهایی که از تاریخ watermark به بعد منتشر شده‌اند
  │
  ▼
۳) گرفتن جزئیات ویدیوها (عنوان، توضیحات و ...)
  │
  ▼
۴) تگ‌گذاری دیدگاه/ربط هر ویدیو (یک‌بار برای هر ویدیو، با LLM)
   - اگر ویدیو به موضوع مرتبط نباشد → رد می‌شود (skip)
  │
  ▼
۵) برای هر ویدیوی مرتبط: گرفتن کامنت‌های تازه
   - فقط کامنت‌هایی که بعد از «آخرین کامنت دیده‌شده‌ی این ویدیو» هستند
   - هم کامنت‌های اصلی و هم ریپلای‌ها
  │
  ▼
۶) محاسبه‌ی امتیاز ریسک ربات برای کل دسته‌کامنت‌های همان ویدیو
  │
  ▼
۷) برای هر کامنت جدا: تگ‌گذاری جغرافیایی خودِ کامنت‌گذار (author_geo.py؛
   بدون LLM — فقط تطبیق عبارت/زبان/کانال، طبق ترتیب text_place → source_community → language_weak)
  │
  ▼
۸) حذف کامنت‌های تکراری (بر اساس content_id) و ساخت رکورد نهایی
  │
  ▼
۹) نوشتن رکوردهای جدید در youtube_comments_v2.jsonl
  │
  ▼
۱۰) به‌روزرسانی watermarkها (تا اجرای بعدی از همین‌جا ادامه بدهد)
  │
  ▼
۱۱) نوشتن یک خط "manifest" در collection_manifest_v2.jsonl
    (خلاصه‌ی این اجرا: چند رکورد آمد، چقدر quota مصرف شد، چه مشکلی پیش آمد و ...)
  │
  ▼
پایان
```

نکات مهم این فلو:
- **quota (سهمیه‌ی روزانه‌ی API یوتیوب)** در هر مرحله چک می‌شود؛ اگر تمام شود،
  اسکریپت به‌جای کرش‌کردن، به‌آرامی متوقف می‌شود و در اجرای بعدی از همان‌جا ادامه می‌دهد.
- هر بار که اسکریپت اجرا می‌شود، حدود ۲ روز آخر را دوباره چک می‌کند (`OVERLAP_BUFFER_SECONDS`)
  چون گاهی یوتیوب در نمایه‌سازی/تأیید کامنت‌ها تأخیر دارد. تکراری‌شدن داده مشکلی ندارد
  چون بر اساس `content_id` فیلتر می‌شود.

## ۴. خروجی‌های نهایی روی دیسک

| فایل | محتوا |
|---|---|
| `data/.../youtube_comments_v2.jsonl` | خودِ کامنت‌ها با همه‌ی فیچرهای بالا |
| `data/.../collection_manifest_v2.jsonl` | خلاصه‌ی هر بار اجرای اسکریپت (چند رکورد، چه بازه‌ی زمانی، چه محدودیت‌هایی) |
| `data/.../video_geo_metadata.jsonl` | کش تگ ربط/دیدگاه هر ویدیو (`is_relevant`, `perspective`) — دیگر جای `geo_*` رکورد کامنت را پر نمی‌کند |
| `checkpoint.json` | وضعیت داخلی برای ادامه دادن اجرای بعدی از همان‌جا (watermarkها، مصرف quota) |

---

## ۵. چطور اجرا می‌شود؟

اجرای دستی:
```
python src/ingestion/youtube_extract_incremental.py
```

اجرای خودکار هفتگی (اسکریپت آماده):
```
scripts/run_youtube_incremental_weekly.ps1
```

پیش‌نیاز: مقدار `YOUTUBE_API_KEY` باید در فایل `.env` تنظیم شده باشد،
وگرنه اسکریپت همان ابتدا با پیام خطا متوقف می‌شود.
(برای فعال بودن هش امن نویسنده‌ها، بهتر است `AUTHOR_HASH_SALT` هم در `.env` ست شود.)

## ۶. تفاوت خلاصه با نسخه‌ی اول (v1)

| | v1 (`youtube_extract.py`) | v2 (`youtube_extract_incremental.py`) |
|---|---|---|
| هر اجرا | کل بازه‌ی پروژه را دوباره می‌گردد | فقط چیزهای جدید را می‌گردد (سریع‌تر) |
| نام نویسنده | ذخیره‌ی مستقیم نام کاربری | فقط هش امن (بدون افشای هویت) |
| آیدی کامنت | ندارد | دارد (`content_id`/`parent_id`) برای جلوگیری از تکرار |
| ریسک ربات | ندارد | دارد (`automation_risk_score`) |
| خروجی | `youtube_comments.jsonl` جدا | `youtube_comments_v2.jsonl` جدا (داده‌های v1 دست‌نخورده می‌مانند) |
