## ۰. تعاریف کلیدی این فصل

این بخش اصطلاحات اصلی مورد استفاده در این فصل را تعریف می‌کند تا تفسیر جامعه آماری، طرح نمونه‌گیری، ارزیابی برچسب‌گذاری و تحلیل‌های آماری در سراسر پروژه یکسان باشد.

> **نکته:** اصطلاحاتی که در فصل اول تعریف شده‌اند فقط در صورتی تکرار شده‌اند که برای فهم طرح نمونه‌گیری یا تحلیل آماری این فصل ضروری باشند.

| اصطلاح | تعریف | کاربرد در این پروژه |
|---|---|---|
| **Target Population — جامعه هدف** | کل جامعه‌ای که پژوهش از نظر مفهومی درباره آن صحبت می‌کند. | تمام گفت‌وگوی عمومی آنلاین مرتبط با موضوع مطالعه؛ اندازه کامل آن قابل مشاهده یا شمارش نیست. |
| **Accessible Population — جامعه قابل‌دسترسی** | بخشی از جامعه هدف که با محدودیت‌های واقعی ابزار، پلتفرم و مسیر دسترسی قابل بازیابی است. | محتوایی که از طریق Queryها، Sourceها و روش‌های دسترسی ثبت‌شده در X، Reddit و YouTube قابل دریافت بوده است. |
| **Sampling Frame — چارچوب نمونه‌گیری** | مجموعه واحدهایی که عملاً امکان ورود به نمونه را داشته‌اند. | محتوای قابل بازیابی از Queryها، Sourceها و Access Routeهایی که واقعاً در پروژه اجرا شده‌اند؛ نه کل محتوای یک پلتفرم. |
| **Retrieved Sample — نمونه بازیابی‌شده** | همه رکوردهایی که Collector واقعاً دریافت کرده است، پیش از اعمال قواعد Eligibility. | پایه ممیزی Collection و ورودی مرحله Harmonization و Eligibility. |
| **Eligible Sample — نمونه واجد شرایط** | رکوردهای بازیابی‌شده‌ای که پس از اعمال قواعد Eligibility برای تحلیل مناسب باقی می‌مانند. | محتوای متنی مستقل و قابل تحلیل که می‌تواند وارد Datasetهای تحلیلی شود. |
| **Analytical Dataset — دیتاست تحلیلی** | نسخه نهایی داده که برای یک تحلیل مشخص استفاده می‌شود. | بسته به هدف می‌تواند `opinion_main`، `unique_text`، `high_confidence` یا `author_balanced` باشد. |
| **Probability Sampling — نمونه‌گیری احتمالی** | روشی که در آن احتمال انتخاب واحدهای جامعه مشخص است. | روش کلی Collection این پروژه نیست؛ فقط مرحله‌ای که واقعاً با Random Sampling و Seed ثبت‌شده انجام شده باشد احتمالی محسوب می‌شود. |
| **Non-Probability Sampling — نمونه‌گیری غیراحتمالی** | روشی که احتمال ورود هر واحد به نمونه معلوم یا برابر نیست. | توصیف اصلی Collection پروژه، زیرا Query، Source، Search Algorithm، حذف محتوا و محدودیت دسترسی بر ورود رکورد اثر دارند. |
| **Query-based Sampling** | جمع‌آوری محتوا با Queryها یا Keywordهای تعریف‌شده. | یکی از مسیرهای اصلی Discovery در هر سه پلتفرم. |
| **Source-based Sampling** | هدایت Collection به Sourceهای مشخص مانند Subreddit، Channel یا Conversation. | برای کنترل و ثبت محدوده منبع داده استفاده می‌شود. |
| **Purposive Sampling — نمونه‌گیری هدفمند** | انتخاب مسیرهای داده بر اساس ارتباط آن‌ها با هدف پژوهش. | Queryها و Sourceهای پروژه بر اساس موضوع مطالعه انتخاب شده‌اند. |
| **Convenience Sample — نمونه در دسترس** | داده‌ای که در محدوده محدودیت‌های واقعی دسترسی و ابزار قابل بازیابی بوده است. | بخشی از نمونه مشاهده‌شده ممکن است به دلیل Pagination، محدودیت تاریخی یا محدودیت Scraper/ابزار ماهیت در دسترس داشته باشد. |
| **Collection Run** | یک اجرای مشخص فرآیند جمع‌آوری با زمان، Query، Source و تنظیمات معین. | واحد عملیاتی برای بازسازی نحوه واقعی Collection. |
| **Provenance** | اطلاعاتی که امکان ردیابی یک رکورد به Source، Query، Collector یا Collection Run را فراهم می‌کند. | مبنای Audit، بازسازی Sampling Frame و درجه‌بندی قابلیت استفاده داده است. |
| **Collection Manifest** | سند ساخت‌یافته‌ای برای ثبت یا بازسازی تنظیمات واقعی Collection. | Query، Source، Sort، Cap، Pagination، خطاها و Coverage واقعی هر Run در آن ثبت می‌شوند. |
| **Run Log** | لاگ اجرای Collector و رخدادهای Collection. | برای بررسی تنظیمات و خطاهای واقعاً رخ‌داده استفاده می‌شود. |
| **Eligibility** | قواعدی که تعیین می‌کند یک رکورد برای تحلیل واجد شرایط است یا خیر. | برای جداسازی محتوای تحلیلی از Context، Audit-only و رکوردهای فاقد متن استفاده می‌شود. |
| **Gold Sample** | زیرمجموعه‌ای با Annotation انسانی معتبر که مرجع ارزیابی مدل است. | برای سنجش کیفیت Sentiment و Stance و تصمیم‌گیری درباره Threshold استفاده می‌شود؛ جایگزین Dataset روند نیست. |
| **Stratified Random Sampling** | تقسیم داده به طبقات و سپس نمونه‌گیری تصادفی در هر طبقه. | برای ساخت Gold Sample با حفظ پوشش Platform، Language و در صورت نیاز زمان/Source استفاده می‌شود. |
| **Seed** | مقدار ثابت برای بازتولیدپذیری Random Sampling. | Seed انتخاب‌شده باید پیش از نمونه‌گیری ثبت و ثابت بماند. |
| **Double Annotation** | برچسب‌گذاری مستقل یک رکورد توسط دو Annotator. | برای سنجش توافق انسانی استفاده می‌شود. |
| **Adjudication** | بررسی و حل اختلاف Annotatorها برای تعیین Label نهایی. | موارد اختلاف پس از Double Annotation با این فرآیند تعیین تکلیف می‌شوند. |
| **Percent Agreement** | درصد مواردی که Annotatorها برچسب یکسان داده‌اند. | معیار ساده توافق انسانی. |
| **Cohen’s Kappa** | معیار توافق دو Annotator با درنظرگرفتن توافق تصادفی مورد انتظار. | همراه با توزیع کلاس‌ها برای ارزیابی توافق انسانی گزارش می‌شود. |
| **Confusion Matrix** | جدول مقایسه Label انسانی با Prediction مدل. | برای هر Task در Model Evaluation گزارش می‌شود. |
| **Precision** | از میان مواردی که مدل یک کلاس را پیش‌بینی کرده، سهم موارد صحیح. | برای هر کلاس گزارش می‌شود. |
| **Recall** | از میان تمام موارد واقعی یک کلاس، سهم مواردی که مدل درست شناسایی کرده است. | برای هر کلاس گزارش می‌شود. |
| **F1-score** | میانگین هارمونیک Precision و Recall. | برای هر کلاس گزارش می‌شود. |
| **Macro-F1** | میانگین F1 کلاس‌ها با وزن برابر برای هر کلاس. | معیار اصلی خلاصه کیفیت مدل. |
| **Accuracy** | نسبت Predictionهای صحیح به کل موارد ارزیابی‌شده. | معیار تکمیلی ارزیابی مدل. |
| **Confidence Threshold** | حداقل Confidence لازم برای پذیرش Prediction مدل. | پس از تعیین در مرحله Development/Evaluation، بدون تغییر روی Dataset اصلی اعمال می‌شود. |
| **Coverage مدل** | سهم رکوردهایی که پس از اعمال Confidence Threshold همچنان Prediction پذیرفته‌شده دارند. | برای نشان‌دادن Trade-off میان کیفیت و میزان داده قابل استفاده گزارش می‌شود. |
| **Weekly Share — سهم هفتگی** | نسبت تعداد رکوردهای دارای یک Label به کل رکوردهای قابل تحلیل در همان هفته. | با رابطه `p̂_w = x_w / n_w` محاسبه می‌شود. |
| **Wilson Confidence Interval** | روش محاسبه فاصله اطمینان برای نسبت‌ها. | برای گزارش عدم قطعیت سهم‌های هفتگی استفاده می‌شود. |
| **Independent Observations** | فرض استقلال Observationها از یکدیگر. | در Social Media ممکن است به دلیل چند محتوا از یک Author یا Parent نقض شود. |
| **Cluster Bootstrap** | Resampling در سطح Cluster به‌جای رکورد منفرد. | در صورت وجود Coverage کافی برای `author_hash` یا `source_parent_id` به‌عنوان تحلیل حساسیت اجرا می‌شود. |
| **Chi-square Test** | آزمون مقایسه توزیع متغیرهای طبقه‌ای میان دو یا چند گروه. | برای مقایسه توزیع Stance میان گروه‌ها یا پلتفرم‌ها استفاده می‌شود. |
| **Fisher’s Exact Test** | آزمون دقیق برای جداول کوچک، به‌ویژه `2×2`. | زمانی استفاده می‌شود که شرایط Chi-square مناسب نباشد. |
| **Mann–Whitney U** | آزمون ناپارامتری برای مقایسه دو گروه مستقل. | در صورت نیاز برای مقایسه Engagement یا متغیرهای رتبه‌ای استفاده می‌شود. |
| **Welch’s t-test** | آزمون مقایسه میانگین دو گروه بدون فرض برابری Varianceها. | در صورت وجود متغیر پیوسته مناسب و برقراری فرض‌های لازم استفاده می‌شود. |
| **Event Window** | بازه تعریف‌شده قبل و بعد از یک رویداد برای مقایسه Outcome. | برای بررسی تغییر Stance پیرامون رویدادهای ثبت‌شده استفاده می‌شود. |
| **Interrupted Time Series (ITS)** | تحلیل سری زمانی برای بررسی تغییر سطح یا روند پیرامون یک رویداد. | فقط در صورت وجود نقاط زمانی کافی و روند پیشارویداد قابل بررسی استفاده می‌شود. |
| **Spearman Correlation** | ضریب همبستگی رتبه‌ای. | معیار اصلی تحلیل ارتباط روندهای Opinion با شاخص‌های مالی. |
| **Pearson Correlation** | ضریب همبستگی خطی. | فقط به‌عنوان Sensitivity Analysis در تحلیل مالی استفاده می‌شود. |
| **Lag** | جابه‌جایی زمانی یک متغیر نسبت به متغیر دیگر. | برای بررسی ارتباط هم‌زمان یا با تأخیر میان Opinion و شاخص‌های مالی استفاده می‌شود. |
| **Benjamini–Hochberg FDR** | روش اصلاح Multiple Testing برای کنترل False Discovery Rate. | برای تعدیل `p-value`ها در تحلیل مالی استفاده می‌شود. |
| **Composition Shift** | تغییر ترکیب نمونه در طول زمان از نظر Platform، Source، Language، Content Type، Author یا Query Version. | برای بررسی اینکه Trend مشاهده‌شده ممکن است ناشی از تغییر ترکیب Sample باشد استفاده می‌شود. |
| **Sensitivity Analysis** | تکرار تحلیل تحت فیلترها یا Datasetهای جایگزین. | برای سنجش پایداری نتیجه در برابر Duplicate، Confidence، Author dominance، Source dominance و سایر تصمیم‌های تحلیلی استفاده می‌شود. |
| **Robustness** | میزان حفظ نتیجه در تحلیل‌های حساسیت. | نتیجه‌ای که تحت تغییرات معقول پایدار بماند Robustتر تلقی می‌شود. |
| **Deduplication** | شناسایی و کنترل رکوردهای تکراری یا بسیار مشابه. | برای کاهش اثر Exact duplicate و Near-duplicate استفاده می‌شود. |
| **Author-balanced Analysis** | تحلیلی که اثر کاربران بسیار پرتکرار را محدود می‌کند. | برای بررسی اینکه Trend توسط تعداد کمی Author بسیار فعال هدایت نشده باشد. |
| **Margin of Sampling Error** | خطای نمونه‌گیری مربوط به طراحی احتمالی با احتمال انتخاب معلوم. | برای تعمیم این نمونه به مردم جهان یا همه کاربران پلتفرم‌ها گزارش نمی‌شود. |

> **قاعده تفسیری اصلی:** درصدها و Trendهای این پروژه درباره **نمونه مشاهده‌شده و واجد شرایط در چارچوب Queryها، Sourceها و محدودیت‌های دسترسی ثبت‌شده** هستند. این مقادیر نباید مستقیماً به کل مردم، کل کاربران یک پلتفرم یا کل گفت‌وگوی آنلاین تعمیم داده شوند.

## ۱. سطوح جامعه و نمونه

ساختار جامعه و نمونه در این پروژه به‌صورت زیر است:

```text
جامعه هدف مفهومی
        ↓
جامعه قابل‌دسترسی از مسیرهای ثبت‌شده سه پلتفرم
        ↓
رکوردهای بازیابی‌شده در Collection Runها
        ↓
رکوردهای واجد شرایط پس از Eligibility
        ↓
Datasetهای تحلیلی اصلی و حساسیت
```

| سطح | تعریف | اندازه قابل گزارش |
|---|---|---:|
| Target Population | تمام گفت‌وگوی عمومی آنلاین مرتبط با موضوع مطالعه | خیر |
| Accessible Population | محتوای قابل بازیابی با Query، Source و مسیرهای دسترسی ثبت‌شده | به‌طور کامل خیر |
| Retrieved Sample | رکوردهای واقعاً دریافت‌شده | بله |
| Eligible Sample | محتوای متنی مستقل و واجد شرایط | بله |
| Analytical Dataset | نسخه نهایی داده مورد استفاده در هر تحلیل | بله |

نمونه این پروژه یک نمونه احتمالی از مردم جهان یا همه کاربران X، Reddit یا YouTube نیست. بنابراین Margin of Sampling Error برای تعمیم به جمعیت عمومی گزارش نمی‌شود و فرمول‌هایی مانند Cochran برای تعیین نمایندگی جمعیت در این طراحی کاربرد ندارند.

## ۲. چارچوب نمونه‌گیری عملیاتی

**Sampling Frame پروژه مجموعه همه محتوای یک پلتفرم نیست.**

Sampling Frame عملیاتی شامل واحدهایی است که در بازه مطالعه از Queryها، Sourceها و مسیرهای دسترسی واقعاً اجراشده توسط تیم امکان بازیابی داشته‌اند.

نسخه نهایی Frame پس از بررسی فایل خام، کد Collector، Config، Manifest و Logهای موجود بازسازی می‌شود.

| پلتفرم | Sampling Frame عملیاتی | واحد اصلی تحلیل | موارد خارج از Frame |
|---|---|---|---|
| X | محتوای عمومی برگشتی از Query، Hashtag یا Conversation واقعاً اجراشده | Post، Reply و Quote دارای متن مستقل | محتوای خصوصی، حذف‌شده، برنگشته از Search یا خارج از دسترسی تاریخی |
| Reddit | Submissionهای کشف‌شده با Query/Source اجراشده و Comment/Reply عمومی بازیابی‌شده از Threadهای آن‌ها | Comment و Reply؛ Submission جداگانه گزارش می‌شود | Threadهای کشف‌نشده، Commentهای حذف‌شده یا Commentهایی که توسط Scraper بازیابی نشده‌اند |
| YouTube | Videoهای کشف‌شده با Query/Channel اجراشده و Comment/Reply عمومی بازیابی‌شده از آن Videoها | Comment و Reply؛ Video فقط Parent Context است | Videoهای کشف‌نشده، Comment غیرفعال/حذف‌شده یا محتوایی که در Pagination بازیابی نشده است |

احتمال ورود هر محتوا به نمونه معلوم و برابر نیست. Search Algorithm، Query، Source، Moderation، حذف محتوا، محدودیت تاریخی، Pagination و محدودیت ابزار بر ورود رکورد اثر دارند.

عبارت استاندارد دفاع:

> «روش Collection یک نمونه‌گیری غیراحتمالی مبتنی بر Query و Source و محدود به دسترسی واقعی پلتفرم و ابزار بود. در محدوده نتایج بازیابی‌شده، هدف نگهداری همه رکوردهای قابل‌دسترسی بود. بنابراین نتیجه درباره نمونه مشاهده‌شده است و Margin of Sampling Error برای جمعیت جهان گزارش نمی‌شود.»

## ۳. راهبرد جمع‌آوری

جمع‌آوری توسط سه Collector انجام شده است. روش واقعی Collection هر پلتفرم از روی فایل خام، کد، Config، Query اجراشده، Manifest و Run Log بازسازی و گزارش می‌شود.

متن این بخش **طرح و منطق ارزیابی Collection** است و به‌تنهایی اثبات نمی‌کند که همه مراحل دقیقاً به همین شکل اجرا شده‌اند.

راهبرد کلی، جمع‌آوری حداکثری در محدوده دسترسی ثبت‌شده هر Query و Source بوده است.

هرجا شواهد نشان دهد همه محتوا قابل بازیابی نبوده است، محدودیت واقعی مانند Sort، Cap، Pagination، محدودیت تاریخی، Rate limit یا محدودیت Scraper/ابزار در `Collection Manifest` ثبت می‌شود. هر مقدار فاقد شواهد با `unknown` مشخص می‌شود.

### ۳.۱ اولویت Collection

ترتیب ترجیح به‌صورت زیر است:

1. نگهداری تمام محتوای قابل بازیابی در Source/Query تعریف‌شده؛
2. اگر محدودیت عددی یا عملی وجود داشته باشد، ثبت دقیق آن در Manifest؛
3. فقط اگر Log یا کد نشان دهد یک مرحله واقعاً با Random Sampling و Seed ثابت انجام شده است، همان مرحله به‌عنوان تصادفی گزارش می‌شود.

وجود Sortهایی مانند Top/Best به‌خودی‌خود معیار مطلوب ورود به نمونه اصلی نیست؛ اگر واقعاً استفاده شده باشند باید به‌عنوان ویژگی همان Run ثبت و در محدودیت‌ها گزارش شوند.

### ۳.۲ روش مناسب این پروژه

با توجه به اینکه احتمال انتخاب هر محتوا معلوم نیست، توصیف مناسب روش کلی عبارت است از:

**نمونه‌گیری غیراحتمالی مبتنی بر Query/Source و محدود به داده قابل بازیابی از مسیرهای واقعی Collection.**

در بخش‌هایی که انتخاب Query یا Source به‌صورت هدفمند انجام شده، مؤلفه Purposive نیز وجود دارد. در بخش‌هایی که محدودیت پلتفرم یا ابزار فقط بخشی از داده را قابل مشاهده کرده است، نمونه مشاهده‌شده ممکن است ویژگی Convenience Sample نیز داشته باشد.

هیچ مرحله‌ای بعداً و بدون مدرک به‌عنوان Random Sampling بازتعریف نمی‌شود.

برای Dataset اصلی، اصل بر استفاده از همه رکوردهای Eligible قابل استفاده است؛ مگر اینکه محدودیت اجرایی مستند و تصمیم قفل‌شده دیگری وجود داشته باشد. Random Sampling بیشتر برای Gold Sample، Audit یا زیرمجموعه‌های توسعه/ارزیابی استفاده می‌شود.

### ۳.۳ تصمیم برای داده موجود

عدم انطباق کامل فایل با Schema جدید باعث حذف خودکار داده نمی‌شود. فایل‌ها و در صورت نیاز رکوردها بر اساس قابلیت استفاده درجه‌بندی می‌شوند:

| درجه | حداقل شواهد | کاربرد |
|---|---|---|
| A | متن، شناسه، زمان، پلتفرم و Provenance قابل ممیزی | همه تحلیل‌های مجاز |
| B | متن، شناسه، زمان و پلتفرم؛ بخشی از Provenance بازسازی‌شده | Trend با گزارش محدودیت |
| C | متن و پلتفرم؛ شناسه یا زمان ناقص | تحلیل توصیفی محدود، نه Trend اصلی |
| D | فایل خراب، داده آزمایشی یا رکورد بدون متن قابل استفاده | قرنطینه و گزارش |

هیچ مقدار نامعلوم برای عبور از Validation جعل نمی‌شود.

## ۵. Gold Sample و توافق انسانی

### ۵.۱ هدف

Gold Sample یک مرجع انسانی برای سنجش کیفیت Annotation و مدل است و جایگزین Dataset اصلی روند نمی‌شود.

### ۵.۲ انتخاب

Gold Sample با **نمونه‌گیری تصادفی طبقه‌بندی‌شده و Seed ثابت** ساخته می‌شود.

طبقات اصلی شامل:

- Platform؛
- Language؛

و در صورت نیاز، کنترل تکمیلی برای پوشش بخش‌های زمانی و Sourceهای بزرگ است.

اندازه Gold Sample، سهم Double Annotation و نحوه تخصیص رکوردها به Pilot/Development و Evaluation **پیش از اجرای کامل Annotation در طرح آماری یا Decision Log تعیین و قفل می‌شوند** و در این فصل به عدد ثابت متعهد نمی‌شوند.

در صورت کوچک‌بودن یک Stratum، تصمیم مربوط به Oversampling، انتخاب کامل Stratum یا ادغام آن باید ثبت شود.

### ۵.۳ توافق انسانی

برای Sentiment و Stance به‌صورت جداگانه گزارش می‌شود:

- تعداد رکوردهای مشترک؛
- Percent Agreement؛
- Cohen’s Kappa؛
- ماتریس اختلاف؛
- تعداد موارد Adjudication.

Kappa همراه با توزیع کلاس‌ها تفسیر می‌شود و یک Threshold ثابت به‌عنوان تضمین کیفیت استفاده نمی‌شود.

## ۶. ارزیابی مدل برچسب‌گذاری

ارزیابی کیفیت مدل فقط روی **Gold Sample یا Held-out Evaluation Sample انسانی** انجام می‌شود؛ Full Dataset برای محاسبه F1 یا Accuracy استفاده نمی‌شود مگر اینکه Gold Label انسانی داشته باشد.

| خروجی | محل/الزام |
|---|---|
| Confusion Matrix | Gold/Held-out Evaluation Sample |
| Precision/Recall/F1 | برای هر کلاس روی Gold/Held-out |
| Macro-F1 | معیار اصلی خلاصه کیفیت مدل |
| Accuracy | معیار تکمیلی |
| Coverage پس از Threshold | Full Annotation Run |
| Failure Rate | Full Annotation Run |
| نتایج به تفکیک زبان | در صورت حجم کافی |
| Cost/Latency | Full Annotation Run |

اگر Confidence Threshold استفاده شود، مقدار آن باید در مرحله Development/Evaluation تعیین و سپس بدون تغییر روی Dataset اصلی اعمال شود.

## ۷. برآورد روند و عدم قطعیت

### ۷.۱ آمار توصیفی

برای کل نمونه، هر پلتفرم و هر هفته تا حد امکان گزارش می‌شود:

- تعداد رکوردها؛
- تعداد Parentهای یکتا؛
- تعداد نویسندگان یکتا، در صورت دسترسی؛
- نرخ Missing؛
- Exact duplicate و Near-duplicate؛
- میانه و IQR طول متن و Engagement؛
- سهم Language، Platform، Source و Content Type؛
- تعداد و سهم هر Label نگرشی.

### ۷.۲ سهم هفتگی

برای هر هفته و هر Label:

\[
\hat{p}_w = \frac{x_w}{n_w}
\]

که در آن:

- `x_w`: تعداد رکوردهای دارای Label موردنظر در هفته `w`؛
- `n_w`: تعداد رکوردهای قابل تحلیل در همان هفته؛
- `p̂_w`: سهم مشاهده‌شده Label.

گزارش هر سهم شامل موارد زیر است:

- `project_week`
- `n`
- تعداد هر کلاس
- سهم کلاس
- فاصله اطمینان ۹۵٪ Wilson
- در صورت نیاز Composition زبان و Sourceهای اصلی

فاصله اطمینان در این پروژه **عدم قطعیت سهم مشاهده‌شده در Dataset** را توصیف می‌کند و نباید به‌عنوان Margin of Sampling Error برای کل جمعیت تفسیر شود.

### ۷.۳ وابستگی رکوردها

رکوردهای Social Media همیشه مستقل کامل نیستند. چند Comment ممکن است از یک Author یا زیر یک Parent مشترک باشند.

روش اصلی در سطح Content اجرا می‌شود و در صورت امکان تحلیل حساسیت شامل موارد زیر است:

1. Cluster Bootstrap بر اساس `author_hash`؛
2. Cluster Bootstrap بر اساس `source_parent_id`.

اگر `author_hash` Coverage کافی نداشته باشد، این محدودیت گزارش می‌شود و Parent-level analysis گزینه عملی‌تری است.

## ۸. حداقل حجم گزارش

هیچ هفته‌ای صرفاً به دلیل حجم کم از Dataset حذف نمی‌شود، اما:

- سهم با `n < 30` فقط به‌صورت توصیفی و با علامت «نمونه کم» گزارش می‌شود؛
- مقایسه زیرگروه با سلول‌های بسیار کوچک ممکن است ادغام یا حذف شود؛
- حد `30` یک قاعده گزارش‌دهی عملی است و تضمین توان آماری محسوب نمی‌شود.

## ۹. آزمون‌های گروهی

آزمون‌های زیر فقط در صورت تناسب با سؤال و برقرار بودن شرایط لازم اجرا می‌شوند:

| پرسش | روش اصلی |
|---|---|
| آیا توزیع Stance میان دو یا چند گروه متفاوت است؟ | Chi-square |
| جدول توافقی کوچک، به‌ویژه `2×2` | Fisher’s Exact |
| Engagement میان دو گروه مستقل | Mann–Whitney U |
| میانگین یک متغیر پیوسته میان دو گروه | Welch’s t-test |

اگر ساختار وابستگی داده با فرض آزمون سازگار نباشد، تحلیل توصیفی یا Bootstrap خوشه‌ای ترجیح داده می‌شود.

## ۱۰. تحلیل رویداد و مالی

### ۱۰.۱ تحلیل رویداد

رویدادهای اصلی و Windowهای آن‌ها از `event_registry_v3.md` گرفته می‌شوند.

برای هر رویداد:

- Outcome اصلی: سهم Stance نسبت به Target مرتبط؛
- Window اصلی: طبق Event Registry؛
- مقایسه اصلی: اختلاف سهم قبل و بعد همراه با CI؛
- Sensitivity Window: طبق Event Registry؛
- روز رویداد در صورت نیاز جداگانه توصیف می‌شود؛
- حجم، Stance و Composition نمونه در Window گزارش می‌شوند؛
- نتیجه هر پلتفرم جداگانه ارائه می‌شود؛
- در صورت تمرکز زیاد داده در یک Parent/Video/Conversation، تحلیل بدون آن Parent نیز تکرار می‌شود.

هر رویداد ثانویه داخل Window در `overlap_note` ثبت می‌شود.

Interrupted Time Series فقط در صورت وجود یک رویداد مناسب، نقاط زمانی کافی و روند پیشارویداد قابل بررسی اجرا می‌شود.

نتایج Event Analysis به‌صورت **ارتباط زمانی** گزارش می‌شوند و رابطه علّی ادعا نمی‌شود.

### ۱۰.۲ تحلیل مالی

- داده هم‌تراز: بازده یا تغییر هفتگی، نه سطح قیمت؛
- ضریب اصلی: Spearman؛
- Lagها: مقادیر از پیش ثبت‌شده در طرح تحلیل؛
- Sensitivity: Pearson؛
- اصلاح چندگانگی: Benjamini–Hochberg FDR؛
- خروجی: ضریب، CI، `p-value` خام و تعدیل‌شده و تعداد هفته‌های هم‌تراز.

## ۱۱. تحلیل Composition Shift

برای هر هفته تا حد امکان بررسی می‌شود:

- سهم پلتفرم‌ها؛
- سهم Sourceهای اصلی؛
- سهم زبان‌ها؛
- سهم News/Report در برابر Personal Opinion؛
- سهم نویسندگان پرتکرار؛
- سهم Duplicate/Near-duplicate؛
- سهم محتوای پرریسک؛
- سهم Query Versionها.

هدف این بخش بررسی این است که آیا تغییر Trend ممکن است ناشی از تغییر ترکیب Sample باشد، نه صرفاً تغییر Sentiment یا Stance.

روند خام در صورت امکان با نسخه‌های Stratified یا Author-balanced مقایسه می‌شود.

## ۱۲. تحلیل حساسیت

حداقل مجموعه تحلیل‌های حساسیت شامل مقایسه‌های زیر است:

1. با و بدون Exact duplicate و Near-duplicate؛
2. با و بدون محتوای High-risk از نظر Automation؛
3. همه Predictionها در برابر High-confidence؛

5. هر پلتفرم با و بدون بزرگ‌ترین Source یا Parent؛
6. روش‌های جایگزین تحلیل مالی و Event Windowهای جایگزین.

هدف Sensitivity Analysis بررسی پایداری نتیجه در برابر تصمیم‌های معقول تحلیلی است.
