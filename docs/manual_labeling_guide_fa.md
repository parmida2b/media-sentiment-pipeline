# راهنمای لیبل‌گذاری دستی کامنت‌ها

این سند برای کسیه که قراره **دستی** روی نمونه‌ای از کامنت‌های سه پلتفرم
(یوتیوب، Reddit و X) لیبل بزنه (annotator). هدف نهایی: این لیبل‌های دستی
(«Gold Sample») بعداً معیار سنجش دقت مدل‌های LLM قرار می‌گیرن — یعنی هرچی
دقیق‌تر و یکدست‌تر لیبل بزنید، انتخاب مدل نهایی هم درست‌تر انجام می‌شه.

⏱️ **زمان تقریبی:** نمونه ۳۰۰ ردیفه (annotator اول) یا ۱۲۰ ردیف (annotator
دوم). هر ردیف معمولاً ۲۰-۴۰ ثانیه — یعنی annotator اول حدود ۲-۳ ساعت، annotator
دوم حدود ۱ ساعت. پروژه محدودیت زمانی داره، پس لطفاً در اولین فرصت شروع کنید و
اگه سوالی پیش اومد توی `notes` بنویسید و رد بشید (لازم نیست منتظر جواب بمونید).

---

## ۱. فایل‌هایی که باید پر کنید

دو فایل CSV در `data/annotated/` براتون آماده شده:

| فایل | برای کی |
|---|---|
| `sample_sentiment_labels.csv` | Annotator اول — **همه‌ی ردیف‌ها** رو پر می‌کنه |
| `sample_sentiment_labels_agreement_subset.csv` | Annotator دوم — فقط همین فایل رو پر می‌کنه (زیرمجموعه‌ای از همون کامنت‌های فایل اول، برای سنجش میزان توافق دو نفر) |

⚠️ **نکته‌ی مهم برای annotator دوم:** قبل از پرکردن، لیبل‌های annotator اول رو
نبینید — وگرنه سنجش توافق (Cohen's Kappa) بی‌معنی می‌شه. مستقل کار کنید.

فایل رو با Excel یا Google Sheets باز کنید (UTF-8 با BOM ذخیره شده، پس فارسی
درست نمایش داده می‌شه).

## ۲. ستون‌هایی که از قبل پر شدن (دست نزنید)

- `sample_id`, `content_id` — شناسه‌ی داخلی، فقط برای ردیابی
- `platform` — `youtube` / `reddit` / `x` (بدونید کدوم کامنت مال کدوم پلتفرمه؛ لحن/سبک نوشتار بین پلتفرم‌ها فرق داره، طبیعیه)
- `language` — زبان تشخیص داده‌شده (`fa`/`en`/`ar`) — تشخیص خودکاره و ممکنه گاهی اشتباه باشه؛ اگه واضح غلطه توی `notes` بنویسید ولی خودتون تغییرش ندید
- `text` — متن اصلی کامنت (همون چیزی که باید لیبل بزنید)
- `post_title` — عنوان ویدیو/پست/رشته‌ای که کامنت زیرش بوده (برای خوندن context مفیده). برای X معمولاً خالیه چون توییت‌ها زیر پست دیگه‌ای نیستن — طبیعیه، جای نگرانی نیست.
- `translation_fa` — اگه برای اون ردیف ترجمه‌ی فارسی موجود بود

## ۳. ستون‌هایی که باید شما پر کنید

`target`, `annotator_id`, `sentiment_label`, `stance_label`, `emotion_label`,
`content_type_label`, `confidence`, `notes`

اول `annotator_id` رو با اسم/شناسه‌ی خودتون پر کنید (همه‌ی ردیف‌ها یکسان).

---

## ۴. چهار محور لیبل‌گذاری — این‌ها **کاملاً مستقل**‌ان

نکته‌ی خیلی مهم: این ۴ محور با هم قاطی نمی‌شن. یک کامنت می‌تونه هم‌زمان از نظر
`sentiment` منفی باشه ولی از نظر `stance` نسبت به یک Target خاص، موافق باشه.
مثال دقیقاً از پرامپتی که به مدل‌ها هم داده می‌شه:

> «این جنگ خیلی خطرناکه، ولی تصمیم دولت آمریکا قابل‌دفاعه»
> → `sentiment = negative` (لحن کلی متن منفیه)
> → `stance = support` نسبت به Target = `T05` (سیاست یا اقدامات دولت آمریکا، چون از تصمیم دولت آمریکا دفاع می‌کنه)

این دو تا مجازن جهت مخالف هم داشته باشن — به زور همسو نکنیدشون.

### ۴.۱ `sentiment_label` — لحن احساسی خودِ متن (بدون توجه به یک Target خاص)
یکی از: `positive` / `negative` / `neutral` / `mixed` / `unclear`
- `mixed`: واضح هم بار مثبت هم منفی داره.
- `unclear`: از متن نمی‌شه لحن رو تشخیص داد.

### ۴.۲ `stance_label` — موافق/مخالفِ یک Target مشخص (نه کل موضوع کلی)
یکی از: `support` / `oppose` / `neutral_or_balanced` / `unrelated` / `unclear`
- `neutral_or_balanced`: صراحتاً درباره‌ی Target صحبت می‌کنه ولی طرف نمی‌گیره.
- `unrelated`: متن اصلاً به این Target نمی‌پردازه.
- `unclear`: به Target می‌پردازه ولی موضع‌گیری مشخص نیست.

**اول باید ستون `target` رو پر کنید** — این‌که کامنت به کدوم یکی از ۶ موضوع زیر
مربوط‌تره (نزدیک‌ترین Target رو انتخاب کنید؛ اگه به هیچ‌کدوم مربوط نبود،
`stance_label = unrelated` بذارید و `target` رو نزدیک‌ترین گزینه یا خالی بذارید).
`T01`-`T03` اصلی‌ان (تحلیل اصلی روی این سه)؛ `T04`-`T06` تکمیلی‌ان (فقط اگه
کیفیت Gold Sample اجازه بده استفاده می‌شن — `docs/pre_analysis_decision_table_v1.md`):

| مقدار ستون `target` | یعنی چی |
|---|---|
| `T01` | اقدام نظامی یا تشدید درگیری |
| `T02` | مذاکره، آتش‌بس و دیپلماسی |
| `T03` | تحریم و فشار اقتصادی |
| `T04` | سیاست یا اقدامات دولت ایران |
| `T05` | سیاست یا اقدامات دولت آمریکا |
| `T06` | پیامدهای انسانی و حفاظت از غیرنظامیان |

### ۴.۳ `emotion_label` — احساس غالب متن (اگه واضح باشه)
یکی از: `anger` / `fear` / `sadness` / `hope` / `joy` / `disgust` / `surprise` / `none_or_unclear`

### ۴.۴ `content_type_label` — نوع متن
یکی از: `personal_opinion` / `news_or_report` / `quotation` / `satire` / `spam` / `unclear`
- `quotation`: متن داره حرف/تیتر خبریِ یه شخص دیگه رو نقل می‌کنه، نه نظر خودِ نویسنده.
- `satire`: متن کنایه/طعنه‌آمیزه — معنای ظاهری کلمات، احساس واقعی نویسنده رو نشون نمی‌ده.
  **اگه satire تشخیص دادید:** `content_type_label = satire` بذارید، ولی
  `sentiment_label`/`stance_label` رو بر اساس **منظور واقعی** نویسنده پر کنید،
  نه خوانش تحت‌اللفظی جمله.
- `spam`: تبلیغ نامرتبط، رفتار بات‌گونه، یا متن تکراری/کلیشه‌ای.

---

## ۵. ستون‌های آخر

- **`confidence`**: عددی بین ۰ تا ۱ — چقدر به لیبل‌های خودتون مطمئنید (۱ =
  کاملاً مطمئن). این فقط برای ماست که بعداً بفهمیم کدوم ردیف‌ها مبهم‌تر بودن.
- **`notes`**: هر نکته‌ای که فکر می‌کنید مهمه (مثلاً «متن نصفه بود»، «طعنه بود
  ولی مطمئن نیستم»، ...) — اختیاریه ولی برای موارد مبهم پر کردنش کمک می‌کنه.

مقادیر مجاز هر ستون دقیقاً همینایی هستن که بالا نوشته شده — چیز دیگه‌ای
تایپ نکنید (حروف بزرگ/کوچیک هم مهمه، همه‌شون lowercase هستن).

## ۶. مراحل بعد از تموم‌شدن لیبل‌گذاری (کار تیم فنی، نه شما)

1. `python src/validation/compute_annotator_agreement.py` — میزان توافق دو annotator (Cohen's Kappa) رو می‌سنجه.
2. اگه توافق پایین بود، ردیف‌های اختلافی با هم بازبینی می‌شن.
3. `python src/validation/evaluate_sentiment_accuracy.py` — دقت مدل‌های LLM رو در برابر لیبل‌های شما می‌سنجه تا بهترین مدل برای لیبل‌زدن روی کل داده انتخاب بشه.

اگه سوالی درباره‌ی یک کامنت خاص داشتید (مثلاً معنیش گنگه یا زبونش تشخیص داده
نشده)، `notes` رو پر کنید و رد بشید — لازم نیست حتماً یه لیبل قطعی بذارید،
`unclear` هم یه گزینه‌ی معتبره.
