# فصل سوم — انتخاب پلتفرم و توجیه منبع

**پلتفرم‌ها:** X، Reddit و YouTube  
**بازه:** `2026-02-28` تا `2026-07-22`

---

## ۰. تعاریف کلیدی این فصل

> **نکته:** اصطلاحاتی که در فصل‌های قبلی، به‌ویژه فصل دوم، تعریف شده‌اند در این بخش تکرار نشده‌اند. این بخش فقط مفاهیم جدید یا ویژه‌ی انتخاب پلتفرم، مسیر جمع‌آوری و مقایسه منابع را پوشش می‌دهد.

| اصطلاح | تعریف |
|---|---|
| **Query-first Collection** | روشی که در آن کشف محتوا از اجرای Queryهای متنی یا هشتگ‌های تعریف‌شده آغاز می‌شود و سپس رکوردهای مرتبط بازیابی می‌شوند. در این پروژه این مسیر، مسیر اصلی X است. |
| **Timeline** | جریان زمانی محتوای منتشرشده توسط یک حساب. Timeline حساب‌های رسمی یا رسانه‌ای می‌تواند برای کشف واژگان و رویدادها استفاده شود، اما به‌تنهایی جامعه Opinion محسوب نمی‌شود. |
| **Seed Account** | حساب اولیه‌ای که برای شروع کشف Source، Conversation، واژگان یا رویدادهای مرتبط استفاده می‌شود. |
| **Discovery Route** | مسیری که از طریق آن یک محتوا یا Source کشف شده است؛ برای مثال جست‌وجوی سراسری یا جست‌وجوی محدود به یک Source. این مسیر برای بازسازی و ممیزی Collection ثبت می‌شود. |
| **Source-scoped Discovery** | روشی که جست‌وجو یا Collection به یک Source مشخص، مانند Subreddit یا Channel، محدود می‌شود. |
| **Source Registry** | فهرست کنترل‌شده‌ای از Sourceهای پروژه که شناسه، نوع، زبان، وضعیت، ریسک انتخاب و زمان اعتبارسنجی هر Source را نگهداری می‌کند. |
| **`source_id`** | شناسه استاندارد Source اصلی که رکورد از آن آمده است؛ مانند Subreddit، Channel، Search scope یا Conversation. |
| **`source_parent_id`** | شناسه Parent مستقیم محتوا؛ برای مثال Submission در Reddit یا Video در YouTube که Comment یا Reply به آن وابسته است. |
| **Search/Keyword Bias** | سوگیری ناشی از این‌که انتخاب واژه‌ها و Queryها تعیین می‌کند چه نوع محتوایی امکان ورود به Dataset را پیدا کند. |
| **Ranking Bias** | سوگیری ناشی از الگوریتم مرتب‌سازی یا رتبه‌بندی پلتفرم. برای مثال نمایش Top/Best به‌جای Recent/New می‌تواند ترکیب محتوای بازیابی‌شده را تغییر دهد. |
| **Precision Audit** | ارزیابی دستی یا سیستماتیک بخشی از نتایج Query برای سنجش این‌که چه سهمی از رکوردهای بازیابی‌شده واقعاً مرتبط با هدف Query هستند. |
| **Power-user Bias** | حالتی که تعداد کمی کاربر بسیار فعال، سهم بزرگی از محتوا را تولید می‌کنند و ممکن است Trend مشاهده‌شده را بیش از حد تحت تأثیر قرار دهند. |
| **Channel Selection Bias** | سوگیری ناشی از انتخاب مجموعه خاصی از Channelهای YouTube که ممکن است دیدگاه‌ها، زبان‌ها یا مخاطبان خاصی را بیش از دیگران وارد نمونه کند. |
| **Subreddit Selection Bias** | سوگیری ناشی از محدودکردن Collection به مجموعه خاصی از Subredditها، به‌طوری که ترکیب محتوای بازیابی‌شده به انتخاب همان Sourceها وابسته شود. |
| **Hashtag Bias** | سوگیری ناشی از اتکا به هشتگ‌ها؛ زیرا همه کاربران مرتبط از هشتگ استفاده نمی‌کنند و کاربران استفاده‌کننده از هشتگ ممکن است با سایر کاربران متفاوت باشند. |
| **Moderation / Deletion Bias** | تغییر ترکیب داده مشاهده‌شده در اثر حذف محتوا، Moderation، بسته‌شدن Commentها یا حذف حساب‌ها. |
| **Access / Collection Limits** | هر محدودیتی در مسیر بازیابی داده، از جمله محدودیت دسترسی تاریخی، Pagination، Rate limit، Cap یا محدودیت Scraper/ابزار، که می‌تواند Coverage واقعی Collection را کاهش دهد. |
| **Collection Cap** | سقف حداکثر تعداد رکوردی که یک Collection Run اجازه دارد بازیابی یا نگهداری کند. این مقدار باید از Manifest واقعی همان Run گزارش شود. |
| **Viral Parent Content** | Parent بسیار بزرگ یا وایرال، مانند یک Submission یا Video، که حجم زیادی Comment/Reply تولید می‌کند و ممکن است Trend کل Dataset را تحت سلطه قرار دهد. |
| **Leave-one-parent-out** | تحلیل حساسیتی که در آن Parentهای بزرگ به‌صورت جداگانه حذف می‌شوند تا مشخص شود نتیجه اصلی وابسته به یک Thread، Video یا Conversation خاص نیست. |
| **Author-balanced Analysis** | تحلیل حساسیتی که سهم نویسندگان بسیار پرتکرار را محدود می‌کند تا تعداد زیاد Post یا Comment از یک Author به‌تنهایی نتیجه را کنترل نکند. |
| **Engagement** | مجموعه شاخص‌های تعامل مانند Like، Score، Reply و Share. این متریک‌ها بین پلتفرم‌ها مستقیماً هم‌مقیاس نیستند و به‌تنهایی به معنای موافقت با محتوا نیستند. |
| **Unweighted Analysis** | تحلیلی که در آن هر رکورد Eligible وزن یکسان دارد و Engagement رکورد وزن تحلیل را تغییر نمی‌دهد. |
| **Engagement-weighted Analysis** | تحلیل حساسیتی که در آن وزن رکوردها براساس Engagement همان پلتفرم تعدیل می‌شود؛ این تحلیل برای مقایسه مستقیم Engagement بین پلتفرم‌ها استفاده نمی‌شود. |
| **`log1p` Transformation** | تبدیل ریاضی `log(1+x)` برای کاهش اثر مقادیر بسیار بزرگ Engagement و جلوگیری از غالب‌شدن چند محتوای بسیار وایرال. |
| **Engagement Cap** | سقف از پیش تعیین‌شده برای وزن یا مقدار Engagement در تحلیل حساسیت تا چند محتوای بسیار بزرگ نتوانند نتیجه را به‌طور نامتناسب کنترل کنند. این مفهوم با `Collection Cap` متفاوت است. |
| **Platform-specific Analysis** | تحلیل جداگانه هر پلتفرم؛ در این پروژه نتیجه اصلی و ترجیحی محسوب می‌شود. |
| **Pooled Observed Analysis** | تجمیع همه رکوردهای مشاهده‌شده سه پلتفرم با وزن مساوی برای هر رکورد؛ فقط خلاصه Dataset موجود است و برآورد جمعیت عمومی محسوب نمی‌شود. |
| **Equal-platform Weighted Analysis** | تحلیل حساسیتی که در آن هر یک از X، Reddit و YouTube وزن کل برابر، یعنی یک‌سوم، دریافت می‌کنند؛ مستقل از تعداد رکوردهای هر پلتفرم. |
| **Geotag** | اطلاعات مکانی مستقیم متصل به محتوا یا حساب که می‌تواند برای تعیین موقعیت جغرافیایی استفاده شود. زبان، Time Zone، Channel یا Subreddit به‌تنهایی Geotag محسوب نمی‌شوند. |
| **Coverage** | میزان پوشش واقعی Dataset از نظر زمان، Source، تعداد Runها و رکوردهای قابل استفاده. Coverage کافی برای هر پلتفرم باید پیش از مقایسه نهایی بررسی شود. |

## ۱. تصمیم پلتفرم

سه پلتفرم برای پوشش سه نوع متفاوت از گفت‌وگوی عمومی انتخاب شده‌اند. این سه محیط معادل یکدیگر در نظر گرفته نمی‌شوند و نتیجه هرکدام ابتدا به‌صورت جداگانه تحلیل می‌شود.

| پلتفرم | نقش در مطالعه | ویژگی متمایزکننده |
|---|---|---|
| X | واکنش سریع به رویداد | محتوای کوتاه، Reply و Quote |
| Reddit | بحث Threadمحور و توضیحی | ساختار Submission–Comment–Reply |
| YouTube | واکنش به محتوای خبری و رسانه‌ای | Commentهای وابسته به Video/Channel |

تعریف رسمی واحدهای تحلیل در فصل اول و Sampling frame هر پلتفرم در فصل دوم آمده است.

## ۲. معیار انتخاب

برای ورود یک پلتفرم یا مسیر داده به مطالعه، حداقل معیارهای زیر در نظر گرفته می‌شوند:

| معیار | الزام |
|---|---|
| دسترسی مجاز | API، Dataset یا روش تأییدشده و ثبت‌شده |
| پوشش زمانی | امکان بازیابی بخشی قابل گزارش از بازه پروژه |
| متن مستقل | مناسب برای Sentiment و Stance |
| Timestamp | قابل تبدیل به UTC |
| شناسه پایدار | برای Deduplication |
| زمینه محتوا | Parent/Conversation/Video در صورت امکان |
| قابلیت ممیزی | Query، Source و Collection Run قابل ثبت |

وجود این معیارها به معنای نمایندگی کامل پلتفرم نیست؛ بلکه مشخص می‌کند داده تا چه حد برای تحلیل پروژه قابل استفاده و قابل ممیزی است.

## ۳. مسیر جمع‌آوری

مسیرهای زیر **طرح مرجع پروژه** هستند. مسیر واقعاً اجراشده برای هر Collector فقط پس از بررسی فایل، کد، Config و Log در `observed_collection_manifest` ثبت می‌شود.

اگر شواهد کافی برای یک تنظیم یا مسیر وجود نداشته باشد، مقدار آن `unknown` ثبت می‌شود و مسیر مرجع به‌جای اجرای واقعی فرض نمی‌شود.

### ۳.۱ X

مسیر اصلی X، Query-first است. Queryهای متنی و هشتگ‌های مکمل با Sort زمانی یا Recent اجرا می‌شوند.

Timeline حساب‌های رسانه‌ای یا رسمی می‌تواند برای کشف واژگان، Sourceها و رویدادهای مرتبط استفاده شود، اما به‌تنهایی جامعه Opinion محسوب نمی‌شود.

### ۳.۲ Reddit

Submission با Query یا Source ثبت‌شده کشف می‌شود و سپس Comment/Reply عمومی مرتبط با همان Thread بازیابی می‌شود.

مسیر کشف عمومی و مسیر Source-scoped با فیلد `discovery_route` از یکدیگر تفکیک می‌شوند تا بعداً مشخص باشد هر Thread از چه مسیر جمع‌آوری وارد Dataset شده است.

### ۳.۳ YouTube

Video از Query و Channelهای ثبت‌شده کشف می‌شود؛ سپس Comment و Reply عمومی مربوط به آن Video بازیابی می‌شود.

خود Video واحد Opinion نیست و عمدتاً به‌عنوان Parent context استفاده می‌شود. برای تحلیل زمانی Commentها، تاریخ خود Comment و نه تاریخ انتشار Video مبنای تعیین هفته است.

## ۴. منابع و Registry

هر رکورد باید تا حد امکان به Source و Parent مناسب متصل شود.

| پلتفرم | Source Unit | فیلد Registry |
|---|---|---|
| X | Search scope، Conversation یا Seed account | `source_id` |
| Reddit | Subreddit و Submission | `source_id`, `source_parent_id` |
| YouTube | Channel و Video | `source_id`, `source_parent_id` |

هر Source باید در Registry دارای اطلاعاتی مانند نام یا ID پلتفرمی، دسته، زبان اصلی، Status، ریسک انتخاب و `verified_at_utc` باشد.

اگر یک Source بعداً غیرفعال یا حذف شود، از Registry پاک نمی‌شود؛ فقط Status آن تغییر می‌کند تا سابقه Collection قابل ممیزی باقی بماند.

## ۵. محدودیت‌ها و کنترل‌ها

روش جمع‌آوری در هر پلتفرم می‌تواند باعث شود نمونه بازیابی‌شده فقط بخشی از محتوای عمومی موجود را پوشش دهد. همچنین ترکیب نمونه ممکن است تحت تأثیر Query، Source، الگوریتم نمایش نتایج، نویسندگان پرتکرار یا محدودیت‌های دسترسی قرار گیرد.

محدودیت‌های اصلی و روش کنترل یا گزارش آن‌ها در جدول زیر آمده‌اند:

| محدودیت | پلتفرم | معنی محدودیت و روش کنترل |
|---|---|---|
| Search/Keyword bias | همه | نتیجه‌ها به Queryها و Keywordهای انتخاب‌شده وابسته‌اند. برای کاهش این Bias، Query familyهای مختلف استفاده و Precision آن‌ها Audit می‌شود. |
| Ranking bias | همه | ترتیب نمایش نتایج می‌تواند ترکیب داده بازیابی‌شده را تغییر دهد. بنابراین Sort واقعی هر Run مانند `Recent`، `New`، `Date` یا `Time` ثبت می‌شود. |
| Power-user bias | X، Reddit | ممکن است تعداد زیادی از محتواها توسط تعداد کمی نویسنده پرتکرار تولید شده باشد. برای بررسی اثر آن‌ها، Author-balanced analysis و در صورت امکان Bootstrap خوشه‌ای در سطح Author اجرا می‌شود. |
| Channel selection bias | YouTube | انتخاب Channelهای خاص می‌تواند ترکیب داده را به سمت همان رسانه‌ها متمایل کند. بنابراین تنوع Channelها و سهم هر Channel در داده گزارش می‌شود. |
| Subreddit selection bias | Reddit | انتخاب Subredditهای خاص ممکن است دیدگاه‌های موجود در نمونه را محدود کند. بنابراین مسیر کشف عمومی و مسیر Source-scoped جداگانه ثبت و گزارش می‌شوند. |
| Hashtag bias | X | اتکا به Hashtag ممکن است فقط بخشی از گفت‌وگو را بازیابی کند. بنابراین Hashtag مسیر مکمل است و جایگزین Query متنی اصلی نمی‌شود. |
| Moderation/deletion | Reddit، YouTube | برخی Commentها ممکن است حذف، غیرفعال یا دیگر قابل بازیابی نباشند. این موارد تا حد امکان به‌صورت Missing یا Data Gap ثبت می‌شوند. |
| Access/collection limits | همه | محدودیت دسترسی، Pagination، Rate limit، Collection Cap یا محدودیت Scraper/ابزار می‌تواند Coverage را ناقص کند. تنظیمات واقعی Run و Coverage زمانی در Manifest ثبت می‌شوند. |
| Language imbalance | همه | ممکن است یک زبان سهم بسیار بیشتری از Dataset داشته باشد. بنابراین حجم نمونه و عملکرد Annotation/Model برای هر زبان جداگانه بررسی می‌شود. |
| Viral parent content | Reddit، YouTube | ممکن است حجم زیادی از Commentها فقط زیر یک Thread یا Video بسیار پربازدید قرار گرفته باشد. برای بررسی وابستگی نتیجه به آن Parent، تحلیل `Leave-one-parent-out` اجرا می‌شود. |

### ۵.۱ Leave-one-parent-out

در این تحلیل، نتیجه ابتدا با Dataset کامل محاسبه می‌شود و سپس با حذف Parentهای بسیار بزرگ یا اثرگذار تکرار می‌شود.

برای مثال، اگر یک Video یا Reddit Thread بخش بزرگی از Commentهای یک بازه را تشکیل دهد، تحلیل بدون آن Parent نیز اجرا می‌شود تا مشخص شود نتیجه اصلی فقط ناشی از همان محتوای وایرال نیست.

### ۵.۲ Author-balanced analysis

در این تحلیل حساسیت، اثر نویسندگان بسیار پرتکرار محدود می‌شود تا یک Author با تعداد زیاد Post یا Comment نتواند به‌تنهایی سهم نامتناسبی در نتیجه داشته باشد.

این تحلیل فقط در صورتی قابل اجراست که شناسه نویسنده یا `author_hash` با Coverage کافی در Dataset موجود باشد.

## ۶. Engagement

متریک‌های Engagement بین پلتفرم‌ها هم‌مقیاس نیستند. برای مثال Like در YouTube، Score در Reddit و Engagement در X مستقیماً یک مفهوم واحد را اندازه‌گیری نمی‌کنند.

همچنین Like، Score، Reply یا Share به‌تنهایی به‌عنوان موافقت با محتوای متن تفسیر نمی‌شوند.

تحلیل اصلی **Unweighted** است؛ یعنی هر رکورد Eligible وزن یکسان دارد.

در صورت اجرای تحلیل Engagement-weighted، این تحلیل فقط:

- درون همان پلتفرم؛
- به‌عنوان تحلیل حساسیت؛
- با تبدیل `log1p`؛
- و با Engagement Cap از پیش تعیین‌شده

انجام می‌شود.

`Engagement Cap` با `Collection Cap` متفاوت است. Collection Cap سقف تعداد رکوردهای قابل جمع‌آوری در یک Run است، در حالی که Engagement Cap فقط برای محدودکردن اثر مقادیر بسیار بزرگ Engagement در تحلیل حساسیت استفاده می‌شود.

## ۷. اصول مقایسه و تجمیع پلتفرم‌ها

سه نوع گزارش از هم تفکیک می‌شوند:

1. **Platform-specific:** نتیجه اصلی و ترجیحی؛ هر پلتفرم جداگانه تحلیل می‌شود.
2. **Pooled observed:** همه رکوردهای مشاهده‌شده با وزن مساوی برای هر رکورد؛ فقط خلاصه Dataset موجود است.
3. **Equal-platform weighted:** هر پلتفرم وزن کل برابر، یعنی یک‌سوم، دریافت می‌کند؛ فقط به‌عنوان تحلیل حساسیت.

`Pooled observed` و `Equal-platform weighted` هیچ‌کدام به معنای تخمین افکار عمومی جهان یا جمعیت کاربران سه پلتفرم نیستند.

هر تفاوت مشاهده‌شده به‌عنوان تفاوت میان **نمونه‌های پلتفرمی مشاهده‌شده** تفسیر می‌شود، نه تفاوت قطعی میان مردم کشورها یا تمام کاربران پلتفرم‌ها.

روش آماری مقایسه، کنترل Composition و قواعد CI در فصل دوم تعریف شده‌اند.

## ۸. جغرافیا

مکان فقط در صورت وجود Geotag یا شواهد مستقیم و قابل دفاع ثبت می‌شود.

موارد زیر به‌تنهایی برای تعیین کشور یا موقعیت نویسنده کافی نیستند:

- زبان متن؛
- Channel؛
- Subreddit؛
- Time Zone؛
- موضوع محتوا.

اگر Coverage معتبر اطلاعات مکانی کافی نباشد، تحلیل جغرافیایی از گزارش اصلی حذف می‌شود.

## ۹. معیار کفایت داده

پیش از تحلیل نهایی، برای هر پلتفرم حداقل موارد زیر گزارش می‌شوند:

- تعداد Run موفق و ناموفق؛
- قدیمی‌ترین Timestamp مشاهده‌شده؛
- جدیدترین Timestamp مشاهده‌شده؛
- `observed_data_cutoff`؛
- تعداد رکورد Raw و Eligible؛
- تعداد هفته‌های دارای داده؛
- سهم Sourceهای اصلی؛
- پوشش `author_hash`؛
- سهم زبان‌ها؛
- نرخ Duplicate، Missing و Failure؛
- محدودیت دسترسی تاریخی؛
- Data Gapهای شناخته‌شده.

پلتفرمی که Coverage کافی ندارد به‌طور خودکار حذف نمی‌شود. در چنین حالتی نتیجه آن به‌صورت تحلیل محدود یا در پیوست گزارش می‌شود و نباید در نتیجه تجمیعی نقش تعیین‌کننده داشته باشد.

اگر یکی از پلتفرم‌ها فقط بخشی از بازه مطالعه را پوشش دهد، مقایسه سه‌پلتفرمی روی **بازه زمانی مشترک** نیز تکرار می‌شود. تحلیل کامل همان پلتفرم جداگانه حفظ می‌شود تا داده موجود از بین نرود.

## ۱۰. منابع رسمی دسترسی

منابع زیر برای مستندسازی قواعد و محدودیت‌های رسمی پلتفرم‌ها نگهداری می‌شوند. وجود یک منبع API در این فهرست به این معنا نیست که همه Collectorهای پروژه الزاماً از API استفاده کرده‌اند؛ مسیر واقعی هر Collector از Manifest، کد، Config و Log همان Run تعیین می‌شود.

- X Developer Platform: <https://docs.x.com/>
- Reddit Data API Terms: <https://redditinc.com/policies/data-api-terms>
- Reddit Developer Terms: <https://redditinc.com/policies/developer-terms>
- YouTube Data API: <https://developers.google.com/youtube/v3>
- YouTube Data API Quota: <https://developers.google.com/youtube/v3/determine_quota_cost>

## ۱۱. نتیجه

استفاده از X، Reddit و YouTube امکان مقایسه سه محیط متفاوت گفت‌وگوی آنلاین را فراهم می‌کند، اما این سه پلتفرم معادل یکدیگر و نماینده مستقیم جمعیت عمومی نیستند.

برای حفظ قابلیت دفاع از نتایج:

- Provenance و مسیر واقعی Collection حفظ می‌شود؛
- نتیجه هر پلتفرم ابتدا جداگانه تحلیل می‌شود؛
- Coverage و Composition هر پلتفرم همراه نتیجه گزارش می‌شود؛
- محدودیت‌های Query، Source، Ranking و دسترسی صریحاً ثبت می‌شوند؛
- تحلیل‌های تجمیعی فقط به‌عنوان خلاصه Dataset مشاهده‌شده یا تحلیل حساسیت استفاده می‌شوند؛
- هیچ وزن نمایندگی جمعیتی به پلتفرم‌ها نسبت داده نمی‌شود.
